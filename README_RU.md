# Network Security Scanner 6.5 — Universal

## Запуск

1. Распакуй **весь архив** в новую папку.
2. В Windows запусти **START_WINDOWS.bat**, либо выполни `python scanner_gui.py`.
3. Введи IP, hostname, CIDR или URL. Профиль **universal** уже выбран.
4. Нажми START SCAN. Для дополнительного поиска CVE по распознанным продуктам/версиям включи Online CVE.

Нужен Python 3.10+ с Tkinter. Файлы `scanner_engine.py`, `scanner_gui.py` и **protocol_checks.py** должны лежать рядом. Других Python-зависимостей у приложения нет. Тестам локального HTTPS нужен `openssl`.

Это сканер доступных сетевых сервисов разных производителей. Он может обнаружить серьёзные проблемы конфигурации, но не гарантирует уязвимости у защищённого устройства. Отчёты не считают доступный порт доказательством возможности взлома.

## Добавленные проверки

| Сервис | Что проверяется | Граница вывода |
|---|---|---|
| VNC / RFB | Предлагается ли SecurityType None | Кандидат HIGH; рабочий стол не открывается |
| SMB2 | Обязательность подписи в NEGOTIATE | MEDIUM при необязательной подписи; relay не выполняется |
| RDP | Ответ на запрос TLS без CredSSP | Кандидат MEDIUM; полный сеанс/NLA-политика после согласования не проверяются |
| MQTT / MQTTS | CONNECT без учётных данных | MEDIUM при принятии; права на темы не проверяются |
| Redis | PING и INFO server | LOW при доступных метаданных; ключи и административные команды не читаются |
| FTP | FEAT, AUTH TLS, handshake | MEDIUM при неподдержанном AUTH TLS; вход и файлы не проверяются |
| SMTP / SMTPS | EHLO, STARTTLS, AUTH в capabilities | Кандидат MEDIUM при объявлении PLAIN/LOGIN до TLS; пароли и письма не отправляются |
| NATS | Приветствие INFO | Кандидат MEDIUM только при явном auth_required=false; сообщения не читаются |
| Memcached | VERSION | Идентификация, без вывода о доступе к кешу |
| RTSP | OPTIONS и соответствие CSeq | Идентификация камер/медиасервисов; видео не запрашивается |

Сохранены HTTP/HTTPS, сертификаты и версии TLS, защитные заголовки/cookies, проверка некоторых опубликованных файлов, SSH-баннеры, Telnet, опциональные DNS/NTP. Добавлена отметка SSHv1 при явном баннере 1.3/1.5. SNMP, перебор учётных данных, SMBv1 и атаки на Wi-Fi не реализованы.

Keenetic остаётся дополнительным модулем: в общем режиме он подключается по обнаруженным признакам. Для ручного ввода его модели/прошивки выбери профиль keenetic. Его встроенный каталог не является общей базой CVE для всех производителей.

## Порты и нестандартные сервисы

Universal расширяет прежний набор портами 2121, 2222, 587, 4222, 5901–5903, 8554 и 11211. Полный перебор всех портов по умолчанию не выполняется. Неизвестные порты читаются на наличие приветствия; произвольные протоколы на них не перебираются.

Поле **TCP ports** заменяет набор портов: например `22,80,443,1883,3389,5900,8000-8100`. Явно указанный в URL порт тоже проверяется.

Поле **Protocol ports** задаёт известный сервис на другом порту: `1884=mqtt,33389=rdp`. Поддержаны имена `vnc,smb,rdp,mqtt,redis,ftp,smtp,nats,memcached,rtsp`. Эти порты включаются в сканирование. Указывай соответствие только если знаешь сервис: неправильный протокол даст неопределённый результат. Для веб-сервиса на необычном порту удобнее передать полный URL. Имплицитный MQTT TLS поддерживается на 8883, SMTP TLS — на 465; переключателя TLS для их произвольных портов пока нет.

```bash
python scanner_engine.py 192.168.0.45 --mode universal --timeout 3 --workers 5 --output device_audit
python scanner_engine.py 192.168.0.0/24 --mode universal --max-hosts 256 --workers 10
python scanner_engine.py 192.168.0.45 --ports 1884 --service-map 1884=mqtt
```

Проверяй только устройства, на аудит которых есть разрешение. По умолчанию ограничение — 256 адресов, максимум 4096. Слишком большая подсеть отклоняется до перебора, включая IPv6.

## Достоверность и CVE

- `FINDING` — наблюдаемое свойство конкретного ответа/конфигурации.
- `POTENTIAL` / `POTENTIALLY_VULNERABLE` — кандидат, требующий проверки условий.
- `UNKNOWN` — ответ неполный, неизвестный, отказ, таймаут или данных не хватает.
- `PASS` относится только к указанной проверке, а не к безопасности сервиса в целом.

Онлайн NVD-поиск работает для явно сопоставленных продуктов: nginx, Apache HTTP Server, OpenSSH, WordPress, vsftpd, ProFTPD, Grafana, Drupal. Новые протокольные модули расширяют проверки конфигурации, а не автоматически добавляют CVE всех обнаруженных продуктов. Неизвестные версии и некоторые версии с суффиксами пропускаются. `NVD_API_KEY` задаётся через окружение; API-ошибки показываются отдельно. Кеш успешных запросов хранится 24 часа.

STARTTLS в FTP/SMTP проверяется без передачи учётных данных. Для него не проверяются доверие сертификату, все версии TLS или обязательность шифрования. Общая проверка сертификатов/версий TLS действует на обнаруженные сервисы с прямым TLS.

MQTT-проверка создаёт кратковременное соединение с уникальным ClientId и clean session, без Will, публикаций или подписок; затем отправляет DISCONNECT. Как и другие проверки, она может появиться в журналах сервера.

## Проверка сборки

Прошли **69 тестов**: предыдущие регрессии, повреждённые и фрагментированные протокольные ответы, границы длины, отмена, отсутствие команд доступа к данным, а также локальные HTTP/HTTPS и MQTT-стенды с полным циклом сканера.

```bash
python -m unittest discover -v
```

Реальные устройства пользователя и внешние адреса из этой среды не проверялись. Живые ответы NVD замокированы. GUI прошёл компиляцию; окно здесь не запущено из-за отсутствующей системной библиотеки Tk. Windows launcher проверен по содержимому, а не выполнением в Windows.

Новые протокольные модули ограничивают размеры ответов и общий бюджет соединения тремя таймаутами. В universal HTTP/TLS/Telnet получают минимум 3 секунды на операцию. Отмена кооперативная; системный DNS может задерживать остановку. Общие HTTP-проверки ограничивают размер ответа, но не задают общий дедлайн медленному серверу. Редиректы не обходятся автоматически.
